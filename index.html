核心设计

Claude Code = Orchestrator
不依赖外部脚本做状态机。Claude Code 主会话本身就是调度者 —— 读 Linear 状态 → 调 Skill/Agent → 写状态，循环直到需要 Human 介入。
Agent + Skill 分层
Agent 独立执行单元，有自己的 context window 和工具权限
Skill 工作流步骤定义，context: fork 隔离执行不污染主上下文
Human 3 个强校验点不可代行

角色矩阵

角色类型职责工具
project-lead Agent 读 Linear 状态 → 决定下一步 → 派发任务 Read, Bash, Skill, Agent, Linear MCP
repo-worker Agent 单个叶子 Task 的代码变更 Read, Edit, Write, Bash
web-researcher Agent 竞品/技术调研搜索 WebSearch
research-phase Skill PRD → TRD → Task 拆分 (fork 隔离) WebSearch, Linear MCP
test-phase Skill Vercel preview 回归测试 (fork 隔离) Bash, WebSearch, Linear MCP
release-phase Skill Preview → Production 发布 (fork 隔离) Bash, Linear MCP
report-phase Skill 全链路产物汇总终报 (fork 隔离) Linear MCP

状态机

主任务 8 态

待启动 ──Human──▶ 调研中 ──Skill──▶ 待开发 ──Human──▶ 开发中
开发中 ──Agent──▶ 待测试 ──Skill──▶ 测试中 ──结果──▶ 待发布 ──Human──▶ 发布中 ──完成──▶ 发布完成

子任务 3 态

Todo ──Agent 领取──▶ In Progress ──Orchestrator 复核──▶ Done

Human 强校验点

必须人卡审 待启动 → 调研中（启动决策）
必须人卡审 待开发 → 开发中（设计放行）
必须人卡审 待发布 → 发布中（上线决策）
必须人卡审 回滚操作 / PRD 非目标段修改

工作流

Step 1 · 调研阶段

research-phase context: fork

判定分支 → 生成 PRD/TRD → Task 拆分 → 全部写入 Linear 评论
分支 A (需求): PRD → UX → UI → TRD → Task 拆分
分支 B (技改): 直接 TRD → Task 拆分

Step 2 · 开发阶段

repo-worker 并发执行

按 step 分组 → 同 step 内并发 fork → 跨 step 串行
每个 Agent: 代码变更 → 自检 → commit → push → merge to main → 汇报 Linear
所有 Task Done → Vercel preview 部署

Step 3 · 测试阶段

test-phase context: fork

HTTP/UI 探针 → 关键链路 happy path → 非目标段反向校验
有 bug → 新建子任务回开发中 / 无 bug → 待发布

Step 4 · 发布阶段

release-phase context: fork

校验 Human 授权 → promote preview → production
无授权 = 拒绝继续 / 回滚必须 Human 手动
